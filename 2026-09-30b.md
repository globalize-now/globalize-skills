### Why the remedy cannot work — the upstream mechanism

New this run. Read in full from [`apps/website/docs/docs/plugin/ecmascript/compatibility.mdx`](https://github.com/swc-project/website/blob/main/apps/website/docs/docs/plugin/ecmascript/compatibility.mdx) (4877 bytes) in `swc-project/website`:

1. Wasm plugin incompatibility was an **`rkyv` layout-matching** problem — serialization logic is compiled into *both* host and plugin, so any AST field change broke old plugins.
2. **`@swc/core` v1.15.0** replaced `rkyv` with self-describing **`cbor`** and added an `Unknown` variant to every AST enum. From that release, plugins are compatible across host versions "to some extent" — field deletions and type changes still break.
3. The plugin side needs exactly two things: **`swc_core >= 47`** and **`--cfg=swc_ast_unknown`**.

Measured against the plugin this repo installs (`lingui/swc-plugin@main`):

| condition | value | clears upstream floor |
|---|---|---|
| `Cargo.toml` `swc_core` | **`77.1.1`** | yes (≥ 47) |
| `.cargo/config.toml` `rustflags` under `cfg(target_arch = "wasm32")` | **`--cfg=swc_ast_unknown`** | yes |

And `6.0.0`-`6.1.0` — the builds the skills tell users to pin back to — are `swc_core@50.2.3`, **also above 47**. So the plugin side was never the variable: pinning back fails on a `1.14.0` host because the **host** predates the cbor change. That is exactly what #69 observed by build (1.15.0 and up transform, 1.14.0 and below fail) and could not explain. **A per-version host-range lookup is the wrong instrument for a floor**, and #69's central claim now has independent corroboration from the upstream side.
