**The public surface change is exactly one option.** Full diff of `dist/compiler/compiler-options.d.ts` is a single addition:

```ts
/**
 * Controls trailing slash canonicalization for localized URLs.
 *
 * Canonicalization happens before URL pattern matching and after URL
 * localization. If omitted, Paraglide keeps its existing trailing slash
 * behavior.
 */
trailingSlash?: "always" | "never";
```

plus one line on the runtime type (`dist/compiler/runtime/type.d.ts`): `trailingSlash: typeof import("./variables.js").trailingSlash;`. The two new internal modules implement it — `normalizeTrailingSlash(url: URL): URL` applies the policy (root `/` always preserved; query and hash untouched), and `execUrlPattern(pattern, url)` matches a canonical URL "while allowing configured patterns to retain their existing trailing slash style."

- The `urlPatterns` guidance at `sveltekit/paraglide.setup.md` L190 is already defensively worded — it tells the agent to "look it up in the Paraglide docs for the installed version before emitting it; do not guess the shape." That instruction stays correct under 2.24.x and needs no correction.

**Why it is still worth an open item.** `trailingSlash` is *not* experimental (unlike `experimentalPerLocaleBuild` in open item 10), it is stable public API on the option type, and trailing-slash policy is a genuine source of redirect loops in SvelteKit — which has its own `trailingSlash` route option in `+layout.js`. Paraglide's canonicalization runs *before* URL pattern matching and *after* URL localization, so a project that sets SvelteKit's `trailingSlash` and paraglide's to different values has two normalizers disagreeing on the same URL. Nothing breaks today because paraglide's default is "keep existing behavior," but the moment the SvelteKit reference documents this option it must document the interaction too. Filed as open item 11 rather than a GitHub issue: no skill is currently wrong, and there is nothing to fix — only something to add.
