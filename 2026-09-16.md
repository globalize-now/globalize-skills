## The finding — a major with no runtime in it, and a range that expired because of it

**→ [#83](https://github.com/globalize-now/globalize-skills/pull/83), ready for review.**

`intl-messageformat` 12.0.0 is the release item 7 has been carrying as a watch since 2026-09-14, when `12.0.0-rc.0` first appeared on the `rc` tag. It went `latest` at 12:27Z yesterday. The version number says "breaking". The diff says something much narrower, and the two together are what makes this actionable.

**Runtime, both tarballs unpacked and diffed.** Five files differ; `index.js` and the IIFE bundle differ by the same two hunks and nothing else:

```diff
-		this.format = (values) => {
+		this.format = ((values) => {
-		};
-		this.formatToParts = (values) => formatToParts(this.ast, ...);
+		});
+		this.formatToParts = ((values) => formatToParts(this.ast, ...));
```

Redundant parentheses the bundler emitted because the source now carries a type assertion. **There is no behavioural change in the published runtime.** The dependency chain underneath says the same thing twice more: `@formatjs/icu-messageformat-parser` 3.5.18 → 3.5.19 changes only `package.json`, and its own bump `@formatjs/icu-skeleton-parser` 2.1.11 → 2.1.12 changes only `index.d.ts` (re-indented JSDoc, `declare` → `export declare`). No runtime file differs anywhere in that chain.

**What the major is for** is in `index.d.ts`: `IntlMessageFormat` becomes `IntlMessageFormat<V extends MessageValues | undefined = undefined>`, and `format` / `formatToParts` route through `MessageFormatFunction<V>` / `MessageFormatToPartsFunction<V>` instead of declaring their signatures inline. Ten type-only exports are added. With the parameter left at its default, `MessageFormatFunction<undefined>` resolves to `UntypedMessageFormat`, declared as the *same* signature v11 shipped. Peers and `engines` are absent in both; `type`, `exports`, `sideEffects`, `main`/`module`/`types` unchanged.

**So the guidance problem is not breakage — it is the range.** Level 1 resolved all 18 manifest specs and found three that no longer land on `latest`:

| spec | resolves to | `latest` | deliberate? |
|---|---|---|---|
| `@lingui/swc-plugin@~6.6.0` | 6.6.0 | 6.7.0 | yes — the ABI pin |
| `@vitejs/plugin-react@^5` | 5.2.0 | 6.1.1 | yes — tracked on #64 |
| **`intl-messageformat@^11`** | **11.2.15** | **12.0.0** | **no — new as of yesterday** |

Item 30's shape exactly: a range that became wrong without anything in this repo changing. The cost is not a broken build, it is that every new Vue project this skill sets up starts one major behind on the package doing *all* of its ICU formatting, and leaves the FormatJS patch train the moment 11.x goes quiet — a line that took five patches in the last six weeks.

**Measured before changing anything** (item 28). Two application trees, each built once then copied so only the one package differs (item 29):

| tree | `intl-messageformat` | parser | `vue-tsc --noEmit`, `strict: true` |
|---|---|---|---|
| control | 11.2.15 | 3.5.18 | rc=0, clean |
| case | 12.0.0 | 3.5.19 | rc=0, clean |

The typecheck is the one that mattered. The skill's `messageCompiler.ts` touches the new generic at exactly one point — `formatter.format(ctx.values)`, where `ctx.values` is vue-i18n's `MessageContext['values']` — and `MessageFormatFunction`'s `[V] extends [MessageValues]` is precisely the kind of conditional that flips silently on an inferred parameter. It does not; the default holds. Rendered output through `i18n.global.t` on vue-i18n 11.4.10 is identical at both versions across every ICU form the skill documents — interpolation, `plural` at 1 and 5, `select`, `selectordinal`, an ICU date skeleton and a `::currency/EUR` number skeleton (the last two deliberately, since the skeleton parser is what actually changed underneath). A real Vite 7.3.6 + `@intlify/unplugin-vue-i18n` 11.2.5 build then SSR-rendered identically at both, `vite build` rc=0 each time.

Six lines change, all the same string: three manifest stacks (`vite-vue-i18n`, `nuxt-vue-i18n`, `quasar-vue-i18n`) and the Step 2 install command in each of the three Vue setup references. `grep -rn "intl-messageformat@"` across the repo returns exactly those six and nothing else outside `library-checks/` — swept from the symptom, and re-run after editing.

**`^11 || ^12` was considered and rejected**, with the reasoning stated in the PR rather than left implicit: both majors work, the runtime is the same bytes, and the disjunction only costs three copy-pasteable `npm install` lines their shell quoting for no benefit. One line per file to flip if Arturs disagrees.
