## Finding 1: `runtimeOnly: false` has not controlled the message compiler since vue-i18n 10.0.0

**→ new draft [`31-vue-i18n-runtimeonly-claim-stale.md`](./pending-issues/31-vue-i18n-runtimeonly-claim-stale.md) + [`.patch`](./pending-issues/31-vue-i18n-runtimeonly-claim-stale.patch) + [`.post23.patch`](./pending-issues/31-vue-i18n-runtimeonly-claim-stale.post23.patch). Unfiled — no write path. PR-shaped, **ready for review**, clean on `main` `48a676ae`, **3 files, `+5/-5`**.**

The claim, at `libraries/vue-i18n/setup.shared.md:537`:

> `runtimeOnly: false` — include the vue-i18n message compiler in the build. … Without this, the compiled bundle drops the message-compiler runtime that our custom function plugs into.

Four sites in three files, enumerated with `grep -rn` over `skills/`: `setup.shared.md` **537** (the option note), **633** (Nuxt cause attribution), **1005** (troubleshooting instruction); `nuxt/vue-i18n.setup.md` **56** (inline comment); `vite/vue/vue-i18n.setup.md` **26** (prose). Quasar carries `runtimeOnly: false` four times with no claim attached and is untouched.

### The option chooses between two copies of the same module

`@intlify/unplugin-vue-i18n@11.2.5`, `lib/index.mjs:217`:

```js
const getVueI18nAliasPath = ({ ssr = false, runtimeOnly: runtimeOnly2 = false }) =>
  `${module}/dist/${module}${runtimeOnly2 ? ".runtime" : ""}.${!ssr ? "esm-bundler.js" : "node.mjs"}`;
```

Both targets are one-line re-exports (`export * from '../dist/vue-i18n.mjs'` / `…vue-i18n.runtime.mjs'`). On `vue-i18n@11.4.13`, the **entire** diff between those two:

```
2515c2515
< // register message compiler at vue-i18n
---
> // register message compiler for jit compilation
```

91 188 vs 91 196 bytes. Both then run `registerMessageCompiler(compile)` unconditionally, and both import `compile` from `@intlify/core-base` on line 6. The `node.mjs` pair (`ssr: true`) differs by the same comment: 67 999 vs 68 007 bytes.

### Dated: true on 9.x, dead at 10.0.0

| vue-i18n | `vue-i18n.mjs` | `vue-i18n.runtime.mjs` | diff lines |
|---|---|---|---|
| `9.14.5` | 109 103 | 109 035 | **12 — a real split** |
| `10.0.0` | 85 095 | 85 103 | 4 (comment only) |
| `11.0.0` | 84 648 | 84 656 | 4 |
| `11.1.0` | 84 660 | 84 668 | 4 |
| `11.4.13` | 91 188 | 91 196 | 4 |

On `9.14.5` the full build falls through to `registerMessageCompiler(compileToFunction)` where the runtime build registers nothing — with JIT off, `runtimeOnly: true` left you with no compiler at all. `compileToFunction` and `__INTLIFY_JIT_COMPILATION__` were removed in **10.0.0**. The note describes 9.x behaviour inside a `^11` stack.

### The real gate, and why it misses us anyway

`lib/index.mjs:29–30` resolves the two options independently: `runtimeOnly` (default `true`) → alias; `dropMessageCompiler` (default `false`) → `define: { __INTLIFY_DROP_MESSAGE_COMPILER__: … }`. In `@intlify/core-base@11.4.13` that flag guards the string branch of the **built-in** `compile` (`core-base.mjs:201`). And `createCoreContext` (`:906`) resolves `isFunction(options.messageCompiler) ? options.messageCompiler : _compiler`, with `compileMessageFormat` (`:1700`) calling it directly — so a custom `messageCompiler` **replaces** `compile`. Both halves of the claim fail: the alias drops nothing, and our function does not plug into anything.

### The Nuxt attribution, which the same file already contradicts

`@nuxtjs/i18n@10.6.0`, `dist/module.mjs`: `bundle.runtimeOnly` **defaults to `false`** (L53) — the skill's snippet sets the default; the alias swap is gated on `!dev && !_prepare && bundle.runtimeOnly` (L2451), so with the default it always takes the full build, which per above is the same module; and `include: localePaths` goes to the plugin **unconditionally** (L~1718). So the pre-compilation is `include` — exactly what L1005 of `setup.shared.md` says correctly, 370 lines after L633 says otherwise.

### Why a PR and not a note

Nothing emitted is wrong and no project breaks — the option is **inert** on `^11`, not harmful. Three reasons it is still worth correcting: **L1005 is a troubleshooting instruction**, so it sends a reader to the wrong knob mid-debug; **four sites state a causal rule** an agent must reason from, and both conclusions it supports are false; and **it hides the real rule** (pre-compilation breaks ICU, the alias is irrelevant) that the same file states once and contradicts four times. **The patch changes no configuration values** — `runtimeOnly: false` stays in every snippet; only the explanation changes. Dropping the option, or adding `dropMessageCompiler: true`, are both defensible and both touch emitted project config or need a real `vite build`; they are in the draft as an open question, not in the patch.
