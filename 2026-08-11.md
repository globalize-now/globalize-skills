## The mover — `next-intl` 4.13.6

**Change (single):** *"Deprecate `requestLocale` param of `getRequestConfig`"* ([#2380](https://github.com/amannn/next-intl/issues/2380), commit `ae770af`; [release](https://github.com/amannn/next-intl/releases/tag/v4.13.6)). Release notes point at the same [`next/root-params` blog post](https://next-intl.dev/blog/nextjs-root-params) as the 4.13.5 `setRequestLocale` deprecation.

**Non-breaking / no pin change.** `package.json` diff 4.13.5 → 4.13.6 is byte-identical except version and the internal sibling deps (`use-intl`, `icu-minify`, `next-intl-swc-plugin-extractor` `^4.13.5` → `^4.13.6`). `engines` still absent; peers **byte-identical** (`next ^12–^16`, `react ^16.8–^19`); `@swc/core`, `po-parser`, `negotiator`, `@parcel/watcher`, `@formatjs/intl-localematcher` all unchanged. Unpacked size 411248 → 411381 B. `^4` admits 4.13.6. It is a deprecation *warning*, not a removal.

**Why it matters to us — it is the other half of open item 0.** The `next/root-params` migration has two moving parts, and next-intl is deprecating them one release apart:

- 4.13.5 deprecated **`setRequestLocale`** (the per-request static-render locale setter) — logged as open item 0 on 2026-08-05.
- 4.13.6 deprecates the **`requestLocale` param of `getRequestConfig`** (the locale read inside `i18n/request.ts`) — the replacement is `await rootParams.locale()`.

**Skill surface for the new (4.13.6) half — 2 files:**

- `skills/globalize-guide/references/languages/js-ts/frameworks/nextjs/app-router/next-intl.setup.md` L199–201 — `getRequestConfig(async ({requestLocale}) => { const requested = await requestLocale; … })`
- `skills/globalize-guide/references/languages/js-ts/libraries/next-intl/po-format.setup.md` L60–61 — same pattern with a `.po` messages import

Both present it as *the* Request Configuration pattern. `getRequestConfig` also appears in `setup.add-ons.md`, `rules.template.md`, and `pages-router/next-intl.setup.md`, but only the two App-Router files above pass/await the now-deprecated `requestLocale` param (pages-router uses a different signature; the others reference the function name only).

**Same caveats as the `setRequestLocale` half:** `next/root-params` requires **Next.js 16.3+**, is **unsupported in Route Handlers & Server Actions**, and `generateStaticParams` is still required. So `requestLocale` must be **kept** as the documented path for Next < 16.3 and for Route Handlers / Server Actions — the edit is additive re-framing, **do not delete** `requestLocale`.

**Decision:** fold this into open item 0 as one consolidated `next/root-params` issue rather than opening a second issue for the same migration. Open item 0 and its issue draft are updated accordingly (below).

**Title:** next-intl 4.13.5–4.13.6 deprecate `setRequestLocale` and `getRequestConfig({requestLocale})` — document the `next/root-params` path in App Router refs

**Labels:** `skills`, `next-intl`, `upstream-change`

**Body:**

next-intl is migrating the App Router locale plumbing to Next.js 16.3's [`next/root-params`](https://next-intl.dev/blog/nextjs-root-params) across two releases:

- `4.13.5` (2026-08-04, [release](https://github.com/amannn/next-intl/releases/tag/v4.13.5)) deprecates **`setRequestLocale`**.
- `4.13.6` (2026-08-10, [release](https://github.com/amannn/next-intl/releases/tag/v4.13.6), [#2380](https://github.com/amannn/next-intl/issues/2380)) deprecates the **`requestLocale` param of `getRequestConfig`**.

Our App Router references teach both as the required patterns, so we now document two deprecated public APIs with no pointer to the modern path.

**Not breaking / no pin change:** `^4` admits both; each is a deprecation *warning*, not a removal; the replacement needs **Next.js 16.3+** while next-intl's peer floor stays `next ^12` (peers byte-identical across 4.13.4 → 4.13.6). Below 16.3, and in Route Handlers / Server Actions, both `setRequestLocale` and the `requestLocale` param remain the mechanism — do **not** delete them.

**Proposed edit (additive):**
- Add a "Next.js 16.3+" note presenting the `next/root-params` path: resolve locale once in `i18n/request.ts` via `await rootParams.locale()` (validate + `notFound()`) instead of `await requestLocale`, then drop `setRequestLocale` calls and manual `getTranslations({locale})` overrides.
- Re-frame the existing `setRequestLocale` **and** `getRequestConfig({requestLocale})` guidance as required for **Next < 16.3** / Route Handlers / Server Actions.
- Caveats to include: `next/root-params` unsupported in Route Handlers & Server Actions; remove any pass-through `app/layout.tsx` (use `global-not-found`); `generateStaticParams` still required.

**Files:**
- `setRequestLocale` half — `.../next-intl/code.md` (L53, 158, 162, 170, 400); `.../nextjs/app-router/next-intl.setup.md` (L31, 45, 49, 449, 467, 495–519); `.../nextjs/app-router/next-intl.convert.md` (L38, 140)
