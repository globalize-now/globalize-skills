## What's in Lingui 6.2.0

From the [v6.2.0 release notes](https://github.com/lingui/js-lingui/releases/tag/v6.2.0):

- **Feature — typed message IDs** ([#2503](https://github.com/lingui/js-lingui/pull/2503), [docs](https://lingui.dev/guides/typed-message-ids)). Opt-in. Adds compile-time type checking for message ID strings against the generated catalog. Worth a brief mention in `i18n-guide/.../lingui/code.md` for users who want stricter TS catalogs — but **not** mandatory; existing untyped usage continues to work.
- **Feature/perf — `pofile-ts` integration** ([#2548](https://github.com/lingui/js-lingui/pull/2548)). Internal PO parser swap. Reported speedups on a 1000-file / 10k-message / 5-locale sample:
  - `extract`: 5.25s → 2.34s (2.24×) single-core, 5.21s → 2.06s (2.41×) dual-core
  - `compile`: 2.74s → 596ms (4.5×) single-core, 1.90s → 588ms (3.23×) dual-core
  - No user-facing API change. The existing `gettext-parser@^9` pin on the few skills that touch `.po` files directly is unaffected (Lingui internalized its own parser, not a switch to `gettext-parser`).
- **Perf — catalog merge key partitioning** ([#2540](https://github.com/lingui/js-lingui/pull/2540)). CLI-only.
- **Fix — peer deps for workspace build tools** ([#2557](https://github.com/lingui/js-lingui/pull/2557)). Bug fix for monorepos that pulled `@lingui/cli` without an explicit `@lingui/core` peer; no skill-visible effect because every skill already installs `@lingui/core` alongside `@lingui/cli`.

**Skill impact assessment.** No mandatory edits. The 6.1.0 → 6.2.0 jump is additive and the `^6` pin already covers it. The typed-message-IDs feature is the only thing worth surfacing to users and is folded into the existing "update Lingui setup skills for v6" carry-forward item below as an *optional addition*.
