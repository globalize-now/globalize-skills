## `vue-i18n` 11.4.0 → 11.4.2 — analysis

Two patch releases shipped within 21 minutes of each other:

- **11.4.1** (2026-05-07T02:19:24 UTC) — [PR #2473 / @kazupon](https://github.com/intlify/vue-i18n/pull/2473): `fix(i18n-t): pass component children as slots`. Resolves [issue #2471](https://github.com/intlify/vue-i18n/issues/2471). When `<i18n-t>` is used with the `as` / `tag` prop pointing at a custom component, Vue 3 dev mode emitted `[Vue warn]: Non-function value encountered for default slot. Prefer function slots for better performance.` The fix wraps slot child rendering in a function (per Vue 3's recommended slot-as-function pattern), eliminating the warning and avoiding the implicit perf hit Vue warns about.
- **11.4.2** (2026-05-07T02:40:29 UTC) — [PR #2474 / @kazupon](https://github.com/intlify/vue-i18n/pull/2474): `fix(formatter): pass component children as slots`. Same fix applied to the matching code path inside `intlify` formatter rendering (the path used when interpolating component slots through the formatter rather than the `<i18n-t>` component directly). Released immediately after 11.4.1 to cover the formatter call site that 11.4.1 missed.

Both patches are pure dev-mode warning suppression + the recommended slot-as-function performance pattern. Same template authoring API (`<i18n-t keypath="…" tag="…">…</i18n-t>` with named slots) — no breaking changes, no migration, no message format changes, no surface change to `t()` / `n()` / `d()` / `useI18n()`.

The internal `@intlify/*` deps (`@intlify/core-base`, `@intlify/shared`, `@intlify/devtools-types`) bumped from 11.4.0 → 11.4.2 in lockstep — vue-i18n pins them at exact match (`"@intlify/core-base": "11.4.2"`), as expected.

**Skill impact:** none. The skill's documented pattern is unchanged.

Users following the skill on `vue-i18n@^11` simply stop seeing the dev warning. The "Prefer `<i18n-t>` over `v-html`" recommendation (line 794) becomes a slightly easier sell — no console noise.
