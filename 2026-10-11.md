### Why this changes the patch and not only the prose

The old patch offered **one** remedy: `overrides: {"@swc/core": "1.16.2"}` — a backwards pin of a transitive host, dropping five patch releases, and exactly the kind of change a reviewer should hesitate over. The opt-out is an environment variable, keeps the host current, and is upstream's own documented answer for this machine class.

So the patch leads with it and keeps the pin as **Remedy 2**, scoped to a resolved host at `1.16.12`–`1.16.13` (no opt-out) or a build where setting an environment variable is not available. Three guardrails are in the new text because each is measured and each is a way to get this wrong: it must be exactly **`1`** (`0` leaves the check on); it is a **no-op below `1.16.17`**; and it **permits symlinked ancestors**, so the patch says to use it where you control the filesystem and not on a host whose cache path other users can rename.

**Scope deliberately held.** The five Vite/SWC stacks reach `@swc/core` transitively through `@vitejs/plugin-react-swc` and have the identical failure mode — but those five files are what **#69** rewrites, so a patch there would collide with an open draft PR. ## Finding 3 (no patch): `vue-i18n@11.4.14` is a security release with zero exposure here, and draft 23 survives its re-measurement
