Both tarballs were downloaded from the registry and unpacked; the diff above is of their shipped `src/`, not of a changelog.

## (F) — three shipped paraglide claims, each run

With no defect to chase, the run spent its remaining budget on claims this log has shipped but never observed. All three are in the paraglide files, all three were exercised on the fixture above, and **all three are correct**.

**1. `messageFormat: "icu"` is load-bearing.** `paraglide.setup.md` L70 states the default `"plain"` reads only `{name}`-style placeholders and renders ICU bodies as literal text, silently. Compiled the same project with the key removed:

| | with `messageFormat: "icu"` | key absent |
|---|---|---|
| compile | exit 0 | **exit 0**, no warning |
| `m.hello_world({name:'Ada'})` | `"Hello, Ada!"` | `"Hello, Ada!"` |
| `m.likes({count:1})` | `"1 like"` | **`"{count, plural, one {# like} other {# likes}}"`** |
| `m.likes({count:5})` | `"5 likes"` | **`"{count, plural, one {# like} other {# likes}}"`** |

Exactly as written, down to the detail that `{name}` still interpolates while plurals do not — which is what makes the omission survive a casual smoke test.

**2. "…or the plugin URL is below `0.1.2`."** Verify step 3 offers that as the second cause of the same symptom. `@globalize-now/paraglidejs-po-format` has three published versions (0.1.0, 0.1.1, 0.1.2); 0.1.1's bundle contains the string `messageFormat` **zero** times, 0.1.2's three times. Compiled against 0.1.1 **with `messageFormat: "icu"` present and correct**: compile exit 0, and `m.likes()` returns the raw `{count, plural, …}` source for both counts. The plugin's `settingsSchema` does not reject the unknown key — it is accepted and ignored. Two different causes, one indistinguishable symptom, and the file already names both.

**3. "The plugin drops `#.` comments when it hydrates the inlang model."** Stated at `paraglide.setup.md` L327 and `paraglide.convert.md` L238, and load-bearing for the PO-over-JSON argument. Read the hydrated model directly: bundle rows carry `id` and `declarations` and nothing else; message rows carry `id`, `bundleId`, `locale`, `selectors`. There is no field a `#.` could occupy, and the `#. Greeting shown on the dashboard` in the fixture appears nowhere in the model. Correct.

**Incidental, recorded not filed:** `@globalize-now/paraglidejs-po-format@0.1.2` implements `key`, `settingsSchema`, `toBeImportedFiles` and `importFiles` — it has **no `exportFiles`**, so `@inlang/sdk`'s `saveProjectToDirectory` refuses with *"cannot write bundles, messages, or variants without an import/export plugin"*. Checked across the boundary: **3.0.3 refuses identically**, so this is not a 3.0.4 regression. It is also not a defect in anything this repo documents — the PO catalogs are hand-authored and Globalize writes them directly, never through the inlang SDK. Noted so the next run does not rediscover it as news.
