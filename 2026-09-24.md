### The gate that was never there

`lingui compile` **without** `--strict` is what every Lingui Verification section prescribes. With every `msgstr` in `app/locales/lv/messages.po` emptied:

```
lingui compile                    rc=0
lingui check missing --verbose    rc=1
  FAIL missing: Found 2 missing translation(s) after applying fallbackLocales.
  app/locales/lv/messages.po: cHOdX1: (Live string)
  app/locales/lv/messages.po: Zb1nVt: (Second string)
lingui check missing --mode catalog   rc=1
```

A green build, a well-formed bundle, and a "localized" site rendering in the source language. This is **item 45's sixth skill** — after #84 (macro transform), #86 (`_locales` bridge), #87 (Lingui catalogs) and #88 (PO key collision) — with one difference: upstream has now shipped the instrument, so the fix is to use it rather than to hand-roll a seventh assertion.

### The sharp edge, which is why this took measuring

`lingui check sync` mirrors **plain `lingui extract`**. Next.js App Router, TanStack Start and the per-route Vite shapes extract with `lingui extract-experimental`. On a per-page fixture (`experimental.extractor.entries`, esbuild installed), running `check sync` **immediately after a clean `extract-experimental`**:

```
FAIL sync: Found 2 out-of-sync catalog file(s).
src/pages/locales/one/en.po: Catalog is out of sync with extract output
src/pages/locales/one/lv.po: Catalog is out of sync with extract output
  rc=1
```

The catalogs were in sync. It is a **false positive**, and the damage is in the obvious remedy: running plain `lingui extract` on that tree — which is exactly what `check sync` compares against — rewrites every entry:

```diff
-msgid "Page one string"
-msgstr ""
+#~ msgid "Page one string"
+#~ msgstr ""
```

So a naive "adopt the new command everywhere" would have made CI permanently red on three stacks and handed users a catalog-destroying fix. #89 splits the guidance by catalog layout and says why.

`lingui check missing` **is** correct on both layouts — `getCatalogs()` appends the experimental catalogs when `config.experimental.extractor.entries` is non-empty (read in `api/catalog/getCatalogs.js`), and on the same fixture it reported both untranslated `lv` entries.

**One more limit, measured:** on a project whose catalog files do **not exist**, `lingui check missing` prints `PASS missing: No missing translations found` and exits **0**. It is a completeness gate, not an existence gate — item 45's own shape, in the new tool. #89 documents it and never lets it stand alone.

### What was measured and found *not* to matter

Two changes in the same release looked like findings and are not. Recorded so they are not re-opened:

- **`@lingui/format-po` header rewrite.** 6.7.0 injects nine empty default headers (`Project-Id-Version:`, `Report-Msgid-Bugs-To:`, `PO-Revision-Date:`, `Last-Translator:`, `Language-Team:`, `Plural-Forms:`, …) into an existing `.po` on every extract, because `pofile-ts` pre-fills them. 6.8.0 copies only the headers the source text actually had. Measured side by side on the same input file. Consequence: the first `extract` after upgrading deletes those nine lines from every committed catalog. **One-time diff churn, no behaviour change**, and a greenfield project never sees it — `getNewHeaders` is unchanged.
- **The `parsePoFile` obsolete-marker workaround** (pofile-ts#22). Tested three ways — obsolete entry last, obsolete entry first, obsolete entries bracketing a live one, plus an obsolete entry whose `msgid` is back in source. **6.7.0 and 6.8.0 produce byte-identical output in all four.** The skills' `lingui extract --clean` path is unaffected.
- **The `@lingui/react` `formatElements` regex.** 6.8.0 widens the tag-name pattern to `[a-zA-Z0-9_](?:[\w.-]*\w)?` so it matches the macro's own tokenizer — before it, a `_t="sign-up"` extracted fine but rendered literally. The skills only ever teach bare alphanumeric names (`_t="tos"`, `_t="privacy"`), which worked on both versions, and `^6` picks the fix up automatically. Left alone.

**Why a PR and not an issue:** the holes, the replacement and the replacement's limits were all produced by commands.
