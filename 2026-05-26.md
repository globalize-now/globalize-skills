- **Within `^6` pin:** yes.
- **GitHub release tag:** none — `https://github.com/lingui/swc-plugin/releases/tag/v6.3.0` returns 404. Continues the straight-to-npm pattern (6.1.0 and 6.2.0 also had no tagged release).
- **swc_core ABI floor:** unchanged. Published `package.json` for 6.3.0 is byte-identical to 6.2.0's (`@swc/core: ^1.15.33` in devDeps). The 6.3.0 bump does not force a fresh swc_core / Next.js / Vite-SWC compatibility re-verification on its own; the carry-over swc-plugin compat re-check from 2026-05-25 still stands and is not made worse.
- **What changed** (reconstructed from tarball diff):
  - **NEW** — two additive options exposed on the helper: `corePackage` (default `['@lingui/macro', '@lingui/core/macro']`) and `jsxPackage` (default `['@lingui/macro', '@lingui/react/macro']`). Lets users override which module specifiers the plugin treats as macro imports. Backward-compatible — defaults match prior behavior.
  - **TS type tightening** — `linguiMacroSwcPlugin()` return type narrowed from `(string | LinguiMacroOptions)[]` to the strict tuple `[wasmPackage: string, config: LinguiMacroOptions]`. Runtime shape was already a 2-tuple, so this is type-level only; could surface as a TS error if a downstream consumer typed the result as a generic array.
  - WASM binary grew ~5.8 KB (2,695,989 → 2,701,824 bytes), consistent with the new option wiring.

**Actionable?** Not today. Worth a small additive mention next time the Lingui setup prose is edited (see open items below): `@lingui/swc-plugin@6.3.0` exposes `corePackage` / `jsxPackage` for projects that re-export the Lingui macros under custom module paths. Defaults preserve current docs verbatim — no required edit.
