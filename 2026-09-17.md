## The finding — a Verification section that cannot see the thing it is verifying

**→ [#84](https://github.com/globalize-now/globalize-skills/pull/84), ready for review.**

The (F) queue head was the Remix pair's Verification section. The claim under audit is the one every Lingui Verification section makes implicitly: *that running these commands and getting exit 0 means the setup works.*

`@lingui/core/macro` and `@lingui/react/macro` each ship a module whose top-level code throws `The macro you imported from "@lingui/…/macro" is being executed outside the context of compilation`. When the Babel/SWC transform runs, the macro import is rewritten and that module never reaches the bundle. When it does not — plugin absent from `vite.config.ts`, or shadowed by a leftover `@vitejs/plugin-react` next to the SWC variant — the module is bundled verbatim and **the app throws on load**.

Four trees, Vite 7.3.6 + React 19 + `@lingui/*@6.7.0`, each a single-install control or a copy of one with exactly one thing changed (item 29):

| tree | macro plugin | `lingui extract` | `tsc --noEmit` | `vite build` | guard string in bundle |
|---|---|---|---|---|---|
| SWC control | `react({ plugins: [['@lingui/swc-plugin', {}]] })` | 1 msg (en+lv) | rc=0 | rc=0 | 0 |
| SWC broken | `react()` | **1 msg (en+lv)** | **rc=0** | **rc=0** | **1** |
| Babel control | `react({ babel: { plugins: ['@lingui/babel-plugin-lingui-macro'] } })` | 1 msg | rc=0 | rc=0 | 0 |
| Babel broken | `react()` | **1 msg** | **rc=0** | **rc=0** | **1** |

Three things in that table are worse than they look.

1. **`lingui extract` is byte-identical across the boundary.** It parses the source with its own Babel pass and never consults the bundler's plugin wiring — so the webext pair's *"Confirm the source catalog holds the four `manifest.*` ids — if not, the macro transform is not running"* is a detector that cannot detect.
2. **`@lingui/vite-plugin`'s `lingui()` was registered in all four trees and failed none of them.** The line carried in `vite/react-babel` and `webext` that *"`@lingui/vite-plugin`'s macro-import check fails at build time"* does not hold for this failure.
3. **The broken build is the smaller, greener one** — 229.31 kB against 231.04 kB. There is no signal anywhere in the output that something is missing.

Per `SKILL.md §2.2` the setup phase reports success on all of this.

**The fix is one assertion**, appended to the six Verification sections that exist:

```bash
! grep -rl --exclude-dir=node_modules --exclude-dir=.git \
    "outside the context of compilation" .
```

`grep` exits 1 on no match, so the leading `!` makes a clean tree the passing case. Nothing outside `node_modules` carries that string unless the bundler put it there — the compiled catalogs from `lingui compile` do not — so it needs **no knowledge of the output directory** and works unchanged on Remix's `build/client`, a Vite `dist/`, and WXT's `.output/`. **Fault-injected in both directions before being trusted**: 0 hits on both working trees, 1 hit on both broken ones, across both transform paths.
