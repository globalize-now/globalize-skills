## What's in `eslint-plugin-lingui 0.14.0`

From the [v0.14.0 release notes](https://github.com/lingui/eslint-plugin/releases/tag/0.14.0):

- **Feature — `require-implicit-id` rule** ([#131](https://github.com/lingui/eslint-plugin/pull/131)). New rule that enforces use of implicit (auto-generated) message IDs and flags explicit `id="..."` props on `<Trans>` / `t\`...\`` calls. Opt-in: not enabled in the recommended config; users who want it have to add it to their ESLint config explicitly. Useful for projects that have standardized on Lingui's content-hash IDs and want lint protection against drift back to hand-rolled IDs.
- **Fix — `no-single-variables-to-translate`** ([#133](https://github.com/lingui/eslint-plugin/pull/133)). Now allows top-level `plural()` / `select()` / `selectOrdinal()` calls. Previously it warned on `t\`${plural(...)}\`` and similar — false positives. No config change needed; just upgrade and the false positives go away.

`peerDependencies` and `engines` are unchanged from `0.13.1` (`eslint ^8.37 || ^9 || ^10`, `typescript ^5 || ^6`, `node >=16`). `dependencies` unchanged (`@typescript-eslint/utils ^8.57.2`, `micromatch ^4.0.8`).

**Skill impact assessment.** One actionable edit:

- **Change:** Bump `'eslint-plugin-lingui@^0.13'` → `'eslint-plugin-lingui@^0.14'` in all 4 package-manager install lines (lines 54, 56, 58, 60) and update the inline comment on line 63 (`If the published current major has advanced past 0.13…` → `…past 0.14…`).
- **Risk:** None. The release is purely additive (opt-in rule + bugfix). No breaking changes, no peer/engine bumps. Users who upgrade get the bugfix for free; the new rule stays off unless enabled.
