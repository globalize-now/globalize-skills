## Finding 1 (new open item 12, medium) — a Node floor nobody checks

`manifest.json` installs 16 distinct npm packages across 20 stacks. **Thirteen declare an `engines.node` floor.** The skill states a Node requirement nowhere:

```
grep -rniE 'node (>=|>= )|engines\.node|"node": ">|Node\.js (18|20|22)|Node (18|20|22)' skills/globalize-guide/
# (no output)
```

`detection.json` (§1.1) has no `nodeVersion` field, so §1.2 has nothing to gate on. Meanwhile §1.2 *does* hard-stop on `@sveltejs/kit < 2.3`, `@remix-run/dev < 2.7`, Remix v1 and CRA, and soft-warns on EOL Rails. The pattern exists; Node is missing from it.

### Effective floor per stack

| Stacks | Effective floor | Set by |
|---|---|---|
| All **9 Lingui stacks** | **`>=22.19.0`** | `@lingui/*@^6` → 6.6.0 |
| `vite-vue-i18n`, `quasar-vue-i18n` | **`>=22.13`** | `@intlify/unplugin-vue-i18n@^11` → 11.2.5 |
| `nuxt-vue-i18n` | **`>= 22`** (transitive) | `@nuxtjs/i18n` 10.6.0 → `vue-i18n@^11.4.8` |
| 2 × next-intl, `sveltekit-paraglide` | none | `next-intl`, `@inlang/paraglide-js` declare no `engines` |
| `rails-yaml`, `android-strings`, 3 × iOS | n/a | no npm packages |

Two details that matter more than the table:

**`@vitejs/plugin-react{,-swc}` declares `^20.19.0 || >=22.12.0` — a disjoint range, not a floor.** It excludes all of Node 21 *and* Node 22.0–22.11. A user on Node 22.5 reads "Node 22, fine" and is wrong. On the three SWC stacks Lingui's `>=22.19.0` subsumes it, so it costs nothing today — but it is exactly the shape hand-written prose gets wrong, which argues for deriving any gate from the manifest rather than writing it into 14 setup files.

**`nuxt-vue-i18n`'s own declaration understates its real floor.** `@nuxtjs/i18n` 10.6.0 says `>=20.11.1`, but depends on `vue-i18n@^11.4.8`, and every `vue-i18n` ≥ 11.4.3 says `>= 22`. This got *stronger* recently: 10.4.1's `^11.4.0` still admitted 11.4.2 (`engines: >= 16`); 10.6.0's `^11.4.8` does not.

### Why medium and not high

User impact depends on package manager. npm warns `EBADENGINE` and proceeds (hard-fails only under `engine-strict=true`); pnpm and Yarn Berry per their strictness settings; bun ignores `engines` entirely. So on a default npm project the install "succeeds" and the failure surfaces two phases later at `lingui extract` or at build — the worst shape for a user, and precisely the class of failure §1.2 exists to move to the front.

### Proposed fix

1. Add `nodeVersion` to `detection.json` (§1.1).
2. Add a **warn**, not a stop — and place it **after** §1.3/§1.5 resolve the variant, because the floor is a property of the *chosen stack*, not the project: a Next.js project on Node 20 is fine on next-intl and broken on Lingui. §1.2 keeps a generic "no candidate stack clears your Node version" stop for the all-candidates-fail case.
3. Derive the floor from an optional `nodeFloor` in `manifest.json` (+ schema), not from prose in 14 files.

Explicitly **not** proposed: adding `engines` to anything the skill emits. This gates the install, not the user's app.

Draft: `pending-issues/12-node-engines-gate.md`.

### A third trigger — because neither of the first two found today's findings

Items 12 and 13 came from a different question. (A) and (B) both ask *"has something I already wrote down gone stale?"* Today's findings came from asking *"does the asserted set still match the shipped set?"* — and both were found by diffing `manifest.json` against something else: once against package `engines` metadata, once against the check's own tracked list.

**Proposed (C) — set-reconciliation.** On quiet runs, diff `manifest.json`'s package set against (i) the tracked set and (ii) each package's `engines`/peer metadata, and report any asymmetry. Unlike (A) and (B), it can surface defects **nobody has written down yet** — the one category this audit practice has never covered. It is cheap, and it found two items on its first run.

**Standing order for quiet runs, in priority order:** (C) set-reconciliation → (B) claim-staleness on any package that published → (A) repo-event path re-grep if a commit moved reference files. If all three are clean, say so and stop; do not invent an audit.
