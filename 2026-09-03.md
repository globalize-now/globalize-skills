## The finding — the paraglide drift check passes on the catalog it exists to reject

### Why this was the target

This run took the paraglide half.

The `msgctxt` claim turned out to be **correct** (below). The fixture built to test it exposed something else in the same file.

### What Add-on 3 ships, and what it promises

`libraries/paraglide/setup.add-ons.md` writes `scripts/check-i18n-catalogs.mjs` into the user's repo, wires it to `npm run i18n:check`, and puts it in the generated `.github/workflows/i18n.yml`. Its stated purpose, verbatim:

> fail the build if a non-base locale file is missing keys present in the base locale … **so untranslated keys surface in review instead of rendering as fallbacks in production.**

The script builds a `Set` of `msgid` values per locale and diffs them. An entry present in every catalog with `msgstr ""` passes.

### What the plugin actually does

`@globalize-now/paraglidejs-po-format@0.1.2`, read out of the published `dist/index.js`:

```js
// importFiles()
if (isUntranslated(entry.msgstr, isPlural)) continue;

function isUntranslated(msgstr, isPlural) {
  const isEmpty = (value) => value === void 0 || value === "";
  if (isPlural) return msgstr.length === 0 || msgstr.some(isEmpty);
  return isEmpty(msgstr[0]);
}
```

An entry with an empty `msgstr` produces **no message for that locale**. Paraglide then aliases the locale to the base one. `paraglide compile` prints `Successfully compiled inlang project.` either way — there is no warning at any layer.

### The matrix — compiled and called, not read

`@inlang/paraglide-js@2.25.0` + `@globalize-now/paraglidejs-po-format@0.1.2`, four fixtures, each run through the plugin's own `importFiles()` **and** through `paraglide compile` with the skill's canonical invocation, then the compiled messages **called**.

| Fixture | plugin `importFiles()` | compiled output | rendered |
|---|---|---|---|
| all four `fr` entries `msgstr ""` | 4 × `@en`, **0 × `@fr`** | `const fr_hello_world = en_hello_world` | `hello_world({name:'Marie'},{locale:'fr'})` → **`"Hello, Marie!"`** |
| `msgstr ""` in **base** `en.po` | `blank_in_base@fr` only | `const en_blank_in_base = () => 'blank_in_base'` | → **`"blank_in_base"`** — the key, as UI text |
| `fr` plural with one empty `msgstr[1]` | **`apples@fr` absent** | `const fr_apples = en_apples` | `apples({count:1},{locale:'fr'})` → **`"# apple"`** |
| wrapped `msgstr` across lines, both locales | both imported | — | — (parser-boundary fixture) |

And on those same trees, the **shipped** script:

```
$ node scripts/check-i18n-catalogs.mjs
✓ all locale catalogs are in sync with the base locale
exit=0
```

Three things the matrix establishes that reading could not:

1. **The base-locale case is worse than the target-locale case and was not on anyone's list.** An empty `msgstr` in `en.po` does not fall back to anything — the compiler emits the bundle id as the message body, so the literal key renders. Same shape as [#72](https://github.com/globalize-now/globalize-skills/pull/72)'s source-catalog caveat, arrived at from the opposite direction.
2. **A partially translated plural loses the work that was done.** `isUntranslated` is `some(isEmpty)` for plurals, so the entry is dropped whole and the translated singular is discarded with it.
3. **ICU-JSON is not the same failure and would have been wrong to copy.** `@inlang/plugin-icu1@1.1.0` imports an empty value as a message with an **empty pattern**: `m.blank()` returns `""` in both locales. Blank UI, not English UI. The JSON branch of the check therefore needed its own wording, which it now has.

### The fix

One file, `libraries/paraglide/setup.add-ons.md`. `keysOf` (a `Set` of keys) becomes `entriesOf` (a `Map<key, translated>`) mirroring the plugin's own import decision; the base locale is checked for empty `msgstr` separately from the target locales, because its failure is different; wrapped `msgstr` continuation lines are joined, since a TMS round-trip reflows them and the old single-line scan would have read a wrapped value as empty. A new **§ What the PO plugin actually imports** carries the three failure modes as a table. The purpose bullet and the two "only enforces key parity" asides are restated to match what the script now does.

**Negative control:** a fully translated four-entry catalog pair — including a `msgctxt` entry and a plural — passes with `exit=0`, and deleting one entry from `fr.po` still reports it under `missing keys`. The original behaviour is preserved, not replaced. On all four fixtures the new `entriesOf` reproduces the plugin's import decision **key for key**.

## (F) — compile-time CDN modules are invisible to every layer of this check

`paraglide.setup.md` writes `project.inlang/settings.json` with:

```json
"modules": ["https://cdn.jsdelivr.net/npm/@globalize-now/paraglidejs-po-format@0.1/dist/index.js"]
```

and says so in as many words: *"inlang fetches and runs the module from that URL at compile time, so there is nothing to `npm install`."* The ICU-JSON variant does the same with `@inlang/plugin-icu1@1`.

Three consequences:

1. **`@0.1` is a floating range** resolving on every user's machine at every compile. The file documents it as floating on purpose (*"`@0.1` resolves the latest `0.1.x`"*).
2. **Neither package was in the tracked set** — that set was seeded from npm packages the manifest names.
3. **Neither is in `manifest.json`**, so yesterday's range sweep never saw them: it walks `packages.runtime` / `packages.dev`, and these are prose in a setup file.

`@globalize-now/paraglidejs-po-format` is **first-party**, and #73 makes its behaviour load-bearing: whether it imports or skips an empty `msgstr` decides whether a project's whole non-base locale renders. A `0.1.3` changing that would reach every existing project on the next `paraglide compile`, with no lockfile entry and nothing here to compare.

**Applied task-side this run:** both added to the tracked set — `@globalize-now/paraglidejs-po-format` **0.1.2** (published 2026-06-03) and `@inlang/plugin-icu1` **1.1.0** (2026-03-26). **Left to a human:** whether `manifest.json` should model a non-npm compile-time module (a per-stack `modules[]` array beside `packages.runtime`/`dev`).
