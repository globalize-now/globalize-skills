## The (F) head, discharged — and the 2026-09-23 characterisation was too narrow

Yesterday's head: *the `@intlify/unplugin-vue-i18n` `treeShaking` regex fallback reporting `hasDynamic: false` after a parse failure.*

**The defect is real, and easier to reach than recorded.** `@intlify/unplugin-vue-i18n@11.2.5` installed and `lib/index.mjs` read (48 182 bytes, `extractKeysFromScript` present, 17 `hasDynamic` occurrences). `extractKeysFromScript` falls back to `extractKeysFromScriptRegex` on **either** an `import('@typescript-eslint/typescript-estree')` failure **or** a `tsEstree.parse` throw, and the regex ends `return { keys, hasDynamic: false }` — hardcoded.

2026-09-23 recorded this as reachable "when the `typescript-estree` import or parse throws", and read the `allowInvalidAST: true` in the parse options as making the parse leg unlikely. **It does not.** Measured on the installed `typescript-estree@8.70.1` with the plugin's exact option set:

| source | `tsEstree.parse` | fallback would report |
|---|---|---|
| `const k='a'; t(k);` | parses — `hasDynamic: **true**` | — |
| `t('a'); const x = 'oops` | **throws** `TSError: Unterminated string literal.` | `keys=["a"] hasDynamic=false` |
| `t('a'); }}}} {{{{` | **throws** `TSError: Declaration or statement expected.` | `keys=["a"] hasDynamic=false` |
| `\0\1\2 t(q)` | **throws** `TSError: Invalid character.` | `keys=[] hasDynamic=false` |
| `@@@ t(k) <<<>>>` | **throws** `TSError: Expression expected.` | `keys=[] hasDynamic=false` |

`allowInvalidAST` tolerates a *recoverable* AST; it does not suppress lexical and syntax errors. So the trigger is **any scanned file with a syntax error** — a mid-edit save during `vite dev`, say — not an exotic module-resolution failure. With `dynamicKeyStrategy: 'ignore'` that silently deletes keys the scan failed to see.

**Still unreachable from this skill, re-verified on current `main` (trigger G, root `skills/`):** `treeShaking` **0** occurrences, `optimizeTranslationDirective` **0**, `scanPatterns` **0**, `dynamicKeyStrategy` **0**. The gate in `lib/index.mjs` is unambiguous — `resolvedOptions.treeShaking ? createUsedKeysCollector(...) : null`, and `treeShakingPlugin` is only pushed when both are truthy. Every `VueI18nPlugin(...)` call site in `skills/` sets `runtimeOnly`, `compositionOnly`, `strictMessage` and nothing else.

**No finding and nothing to file.** The watch is worth keeping in its corrected form: if this skill ever recommends `treeShaking`, the recommendation must come with `dynamicKeyStrategy: 'keep-all'` (the default) and never `'ignore'`. Item **57** style — recorded so it is not re-derived.
