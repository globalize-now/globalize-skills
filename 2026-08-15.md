### The mover — `@intlify/unplugin-vue-i18n` 11.2.5

Release notes ([bundle-tools v11.2.5](https://github.com/intlify/bundle-tools/releases/tag/v11.2.5)) list two entries: `fix(unplugin-vue-i18n): invalidate glob locale modules on Vite HMR` (#603) and `chore(release): generate changelog before tagging` (#607).

Tarball diff (11.2.4 vs 11.2.5), which is the authoritative characterization here:

- **File list: identical.** Nothing added, nothing removed. No `.d.ts` change anywhere — so **no public API or option-type surface moved**.
- **Only runtime change:** `handleHotUpdate` in `lib/index.cjs` and `lib/index.mjs`. Old behaviour invalidated the single `INTLIFY_BUNDLE_IMPORT_ID` virtual module only when the changed file matched `RE_RESOURCE_FORMAT`. New behaviour looks the changed file up in a `realPathToVirtualId` map (SFC `<i18n>` custom blocks / per-file virtual ids), separately checks whether the file falls inside the plugin's `include`/`exclude` filter, unions the affected modules with Vite's own `modules` list, and returns early when it has nothing to add. Net effect: editing a locale file matched by a glob `include` now actually hot-reloads instead of being missed.
- **`package.json`:** `engines` `{"node": ">= 22.13"}` unchanged; peers `vue ^3.2.25`, `vite ^6.0.0 || ^7.0.0 || ^8.0.0`, `vue-i18n *`, `petite-vue-i18n *` and their optional flags unchanged (key order differs, values identical); every dependency range unchanged except `@intlify/bundle-utils` `11.2.4` → `11.2.5`.

Skill-surface check — **no hit anywhere**:

- grep `skills/` for `handleHotUpdate` = 0 hits; for `HMR` / `hot reload` / `hot-update` = 0 hits. No skill asserts anything about dev-server invalidation behaviour.
- Both `VueI18nPlugin({...})` call sites the skill emits (`frameworks/vite/vue/vue-i18n.setup.md` L39-45, `frameworks/quasar/vue-i18n.setup.md` L70-75 and L112) deliberately pass **no `include`** — commented in-file as "keep catalogs as plain JSON so the custom ICU compiler can process raw strings at runtime". The fix's `include`-filter branch is therefore inert for the config the skill generates; only the `realPathToVirtualId` branch (SFC custom blocks) could ever apply.
- Install lines are already `'@intlify/unplugin-vue-i18n@^11'` (both setup files L19, plus `manifest.json` L220 / L266), so `^11` picks up 11.2.5 with no edit.
- The Nuxt path does not install this package directly; it comes in transitively via `@nuxtjs/i18n`.

Verdict: **dev-ergonomics bugfix, zero skill surface, no pin change, no issue.** Not even worth a watch item — the changed hook has no documented contract the skills rely on.
