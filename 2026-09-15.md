## `next-intl` 4.14.4 → 4.14.5 — a real mechanism change with no guidance consequence

The one release in the window, and it is not the `package.json`-only patch the version number suggests. Five shipped modules changed:

```diff
-function getBasePath(pathname, windowPathname = window.location.pathname) {
-  if (pathname === '/') return windowPathname;
-  else if (windowPathname.endsWith(pathname)) return windowPathname.slice(0, -pathname.length);
-  else return '';
+function getBasePath() {
+  try {
+    // Provided via `env` setting in `next.config.js` via the plugin
+    return process.env._next_intl_base_path || '';
+  } catch { return ''; }
 }
```

So the base path moved from a **client runtime derivation** to a **build-time env var**, which `createNextIntlPlugin` now injects from `nextConfig.basePath` alongside the existing `_next_intl_trailing_slash`. `syncLocaleCookie` loses its `pathname` parameter; `BaseLink` and `createNavigation` stop calling `usePathname` entirely — which also removes the Suspense boundary that locale-changing `<Link>`s needed under Cache Components (the comment documenting that requirement is deleted in this release).

**Measured, not reasoned about.** Next.js 16.3.4 / React 19.3.0, three config shapes, `env` read from `.next/required-server-files.json`:

| `next.config.mjs` | `config.basePath` | `config.env` |
|---|---|---|
| `withNextIntl(nextConfig)` with `basePath` in `nextConfig` — **what the skill writes** | `/dashboard` | `{"_next_intl_base_path":"/dashboard"}` ✅ |
| `withNextIntl(withBase({}))` — outer helper runs first | `/dashboard` | `{"_next_intl_base_path":"/dashboard"}` ✅ |
| `withBase(withNextIntl({}))` — an outer plugin supplies `basePath` **after** `withNextIntl` ran | `/dashboard` | `{}` ❌ |

**Nothing to change.** The skill's App Router and Pages Router files both wrap the config object that carries the project's existing options, which is row 1. Row 3 is reachable only from a config-composing plugin that *injects* `basePath`, which this repo documents nowhere — `grep -rn "basePath"` across `skills/` returns four hits, all of them unrelated local variables in vue-i18n and lovable-i18n. And the failure in row 3 is a cookie written at `path=/` instead of `path=/dashboard`: a **wider** scope, not a broken app. Recorded as open item 42 rather than a PR or an issue; re-open if the repo ever documents `basePath`.

Peers are byte-identical across 4.14.4 → 4.14.5 (`next ^12–^16`, `react ^16.8–^19`), `engines` absent in both. Users on `^4` get this for free.
