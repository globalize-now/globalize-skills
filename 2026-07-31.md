### `@nuxtjs/i18n` 10.5.0 → 10.6.0 (published 2026-07-30T10:49Z)

Minor release, two themes:

- **Performance.** Locale messages are no longer bundled into the server build as JS, no longer shipped as client chunks when served from the messages endpoint, and no longer copied on every SSR request. Maintainer benchmarks (10 locales × ~2,000 messages, 10 pages, M4 Pro / Nuxt 4.5): build 9.2s → 5.7s (**38% faster**), peak build memory 3.6 GB → 2.5 GB (**30% less**), module build output 12.9 MB → 3.2 MB (**75% smaller**), SSR throughput 785 → 1722 req/s (**2.2×**). Gated by a **new `experimental.optimizeMessageBundling` option that is ON by default** in 10.6.0 (set `false` to disable if a build breaks). Only affects messages the module can read at build time (`.json`/`.yaml`/`.json5`); `.ts`/`.js` locale files are unchanged.
- **Domain routing.** `differentDomains` and `multiDomainLocales` now agree on which locale each domain serves; `hreflang`/canonical name one domain per locale; a domain serving exactly one locale is treated as that locale's default again (`domainDefault` no longer needed for it); plus a new "restrict locales to a subset of `domains`" feature (#4085).

`engines.node` stays `>=20.11.1` (Nuxt still inherits the Node ≥ 22 floor transitively via `vue-i18n`, whose floor bumped `^11.4.6` → `^11.4.8`). Other transitive floors bumped: `@intlify/core`/`@intlify/shared` → `^11.4.8` (+ `@intlify/message-compiler ^11.4.8` added), `@nuxt/kit` → `^4.5.1`, `unrouting` `^0.1.7` → `^0.2.2`, `oxc-parser`/`oxc-transform` → `^0.141.0`, `unhead` → `^3.2.3`, `devalue` → `^5.8.2`, `confbox ^0.2.4` added. **`^10` admits it. `grep skills/` for `defineI18nRoute`/`customRoutes`/`definePageMeta`/`differentDomains`/`multiDomainLocales` = 0 hits → no skill surface affected. Not actionable.** This is the maintainer's domain-consolidation work landing (the standing watch): they made the two domain features *consistent* here rather than merging into one option — the merge is still exploratory for v11.
