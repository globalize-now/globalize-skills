## Actionable items

### 1. NEW — add a Node ≥ 22.13 gate to the Vue i18n setup
**Severity: medium.** Pins are still correct; the skill is missing a preflight.

The intlify org dropped Node 20 across its packages in mid-May:

- `vue-i18n` `engines.node`: `>= 16` (11.4.2) → **`>= 22`** (11.4.3, 2026-05-17). The 11.4.3 release notes file this under "💥 Breaking Changes" — "chore!: drop Node.js 20 support" (#2478) — even though the version number only moved a patch.
- `@intlify/unplugin-vue-i18n` `engines.node`: **`>= 22.13`** as of 11.2.3 (the bump landed in the 11.2.x line, first published 2026-05-13).

The skill installs both for the `vite-vue-i18n` and `quasar-vue-i18n` variants (`runtime: vue-i18n@^11, intl-messageformat@^11` + `dev: @intlify/unplugin-vue-i18n@^11`). With caret pins, a fresh install now resolves `vue-i18n@11.4.4` + `@intlify/unplugin-vue-i18n@11.2.3`, both of which emit `EBADENGINE` on Node 18 or 20.

There is currently **no Node-version handling anywhere in the Vue references** — `grep -n node skills/.../vue-i18n/` finds only `node:fs` imports and `node -e` script lines.

Suggested action (mirrors the Lingui v6 gate already on the backlog):

- Add a Node ≥ 22.13 detection gate to `skills/i18n-guide/references/languages/js-ts/libraries/vue-i18n/setup.shared.md` and the three framework setup files (`vite/vue/vue-i18n.setup.md`, `quasar/vue-i18n.setup.md`, and check `nuxt/vue-i18n.setup.md`).
- If the project is on Node < 22.13, prompt to upgrade Node, or fall back to pinning `vue-i18n@~11.4.2` + `@intlify/unplugin-vue-i18n@~11.1.2` (the last Node-16-compatible line).
- **Verify the Nuxt variant separately.** `nuxt-vue-i18n` installs `@nuxtjs/i18n@^10`, which pulls `vue-i18n` transitively — confirm whether `@nuxtjs/i18n@10.4.0` resolves a Node-22-requiring `vue-i18n` and whether that surfaces as an install warning for Nuxt projects on Node 20.

Affected files:
