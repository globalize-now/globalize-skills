## Finding: the PO plugin's `messageFormat: "plain"` failure is mischaracterised in six places

**→ new draft [`34-paraglide-plain-mode-select-mischaracterised.md`](./pending-issues/34-paraglide-plain-mode-select-mischaracterised.md) + [`.patch`](./pending-issues/34-paraglide-plain-mode-select-mischaracterised.patch). Unfiled — no write path. PR-shaped, **ready for review**, clean on `main` `48a676ae`, **5 files `+15/-7`**, branch `library-check/paraglide-plain-mode-symptoms` when a write path exists.**

This is (F)'s output, and for once the head was **exactly the one carried**: 10-07 wrote that the `messageFormat` warning in `paraglide.setup.md` *"is now the only unmeasured behavioural claim left in the two Paraglide setup files, and the harness to measure it is already built."* Both halves were true.

### The claim

`paraglide.setup.md` L70, in the settings section of the **default** (PO) setup file:

> **`messageFormat: "icu"` is required and load-bearing.** The default is `"plain"`, which reads only `{name}`-style placeholders and renders ICU `plural` / `select` / `selectordinal` bodies as **literal text** — silently, with no build error.

Five other places restate it: `paraglide.setup.md` L380, `paraglide.convert.md` L308, `rules.template.md` L289 (**in the file the skill installs into the user's repo**), `json-format.convert.md` L25, and `SKILL.md` L608 / L683.

### What was measured

`@inlang/paraglide-js@2.26.0` (what `^2` resolves to) + `@globalize-now/paraglidejs-po-format@0.1.2` (what the `@0.1` CDN pin resolves to). Eight bodies, one catalog, standalone `paraglide-js compile`, rendered through `node`. The **only** difference between the columns is the presence of `"messageFormat": "icu"`.

| `msgstr` | plain: compiled `Inputs` | plain: rendered | icu (control) |
|---|---|---|---|
| `Hello {name}` | `{ name }` | `"Hello Ada"` | `"Hello Ada"` |
| `{count, plural, one {# like} other {# likes}}` | `{}` | `"{count, plural, one {# like} other {# likes}}"` | `"1234567 likes"` |
| `{count, plural, one {{count} like} other {{count} likes}}` | `{ count }` | **`"{count, plural, one {1234567 like} other {1234567 likes}}"`** | `"1234567 likes"` |
| `{count, plural, one {{count, number} like} …}` | `{}` | literal source | `"1,234,567 likes"` |
| `{g, select, female {She} male {He} other {They}} replied` | **`{ She, He, They }`** | **`"{g, select, female undefined male undefined other undefined} replied"`** | `"She replied"` |
| `{g, select, female {{n} girls} other {{n} others}} here` | `{ n }` | **`"{g, select, female {1234567 girls} other {1234567 others}} here"`** | `"1234567 girls here"` |
| `{n, selectordinal, one {#st} …}` | `{}` | literal source | `"1234567th place"` |
| `You have {amount, number} points` | `{}` | **`"You have {amount, number} points"`** | `"You have 1,234,567 points"` |

The compiled artifact is the proof, not the rendering — `messages/replied.js` under plain:

```js
/** @typedef {{ She: NonNullable<unknown>, He: NonNullable<unknown>, They: NonNullable<unknown> }} RepliedInputs */
const en_replied = (i) => (`{g, select, female ${i?.She} male ${i?.He} other ${i?.They}} replied`);
```

and the cause, from the plugin's own `dist/index.js`:

```js
const format = settings[PLUGIN_KEY]?.messageFormat ?? "plain";   // L10360 — the default
if (format === "plain") { const { pattern, declarations } = parsePattern(msgstr); … }
```

`parsePattern` reads every `{…}` as a `{name}` placeholder. In a `select`, the **branch bodies** are `{…}`. A plural branch written with `#` has no brace — which is the only reason the `#` and `selectordinal` rows stay literal.

### Build signal: silent, confirmed, in both modes

```

√ [paraglide-js] Successfully compiled inlang project.
rc=0    stderr: 0 bytes    grep -ic warn on stdout + stderr: 0 / 0
```

Measured with the plural, the select and the bare `{amount, number}` in the same catalog. **There is no warning to read**, so the Verify sections' *"Exit 0 is not the check — read the warnings"* has nothing to work with on this path.

### Typecheck signal: `select` is not silent, and nothing else is caught

`tsc --noEmit`, `allowJs`, `types: []`:

```
src/callsite.ts(3,30): error TS2353: Object literal may only specify known properties,
                       and 'g' does not exist in type 'RepliedInputs'.
```

- `m.replied({ g: 'female' })` → **TS2353**, **with and without `checkJs`** (measured both: the JSDoc `@typedef` is read off the emitted `.js` whenever `allowJs` is on).
- `m.likes({ count: 5 })` and `m.points({ amount: 1000 })` → **no error**, because their `Inputs` is `{}` and `{}` accepts any object, so excess-property checking never fires.

`SKILL.md:572` already prescribes `tsc --noEmit` in Phase-2 verification. **The signal is on a command the skill runs today, and no file mentions it.**

### The half that is correct and stays

A **malformed** ICU `msgstr` under `messageFormat: "icu"` *is* silently imported as literal text — measured: an unclosed `{count, plural, one {# like} other {# likes` compiles **exit 0** and emits the body verbatim, identically under plain. `rules.template.md` L289's first sentence is accurate and the patch does not touch it; only the diagnostic that follows is extended.

### Four corrections, and what ships

1. a `select` renders `undefined`, not literal text — an agent handed L289's *"renders as raw `{count, plural, …}`"* diagnostic has no stated cause for what it is looking at;
2. a `select` is **not** silent — it is the one construct the prescribed typecheck catches, and three files call the render check *"the only signal"* / *"the only check"*;
3. a plural written `{count}` instead of `#` is a **third** symptom — scaffolding plus interpolated count;
4. the enumeration is too narrow — a bare `{amount, number}` is neither plural nor select nor selectordinal and is broken, silently.

The patch replaces L70's sentence with a three-row symptom table naming `{amount, number}` and the `TS2353` asymmetry; makes both Verify steps require **a plural *and* a select**; extends the installed diagnostic in `rules.template.md`; and corrects the two restatements in `SKILL.md` and the phrase in `json-format.convert.md`.

**The judgement call: a table in a setup file rather than one more sentence.** The three symptoms share one cause and one fix, so a sentence is tempting — and rejected, because the whole defect is that an agent cannot get from the symptom back to the cause, and a prose list of three confusable symptoms is how the current single sentence came to be written. Cost: ~9 lines in one block quote. **Correcting L70 and L289 alone is a strict subset**, so it is the easy call to overrule.

**Deliberately not touched:** any `#` occurrence. That is draft 33's subject — which is also why the two commute.
